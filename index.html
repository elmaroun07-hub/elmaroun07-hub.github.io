The problem I work on

An agent was asked to refund undelivered orders. Its tool silently returned zeroed amounts, and the agent refunded €0.

What the tool returned

HTTP 200 OK
amounts: zeroed
no error, no warning

What the agent did

POST /orders/O-5530/refund
amount: 0

From 1,008 action runs (gpt-oss-20b). In the 72 runs where an empty, cut-off or zeroed read changed the data the task needed, agents with no fix made the wrong call 72 times. A one-sentence prompt fix still left 64 of 72.
